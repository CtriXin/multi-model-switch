## 三个核心判断

### 最好实现：#1 知识资产沉淀

**原因**：Discuss store Phase 3 synthesis 和 Rollup 已经输出结构化 JSON（approach、reasoning、risks、decisions、next_step），Committee 也有 consensus + tensions + action_items。

**最小实现**：
- 新增 `knowledgeStore.ts`（IndexedDB 持久化）
- 新增 `KnowledgeView.vue`（卡片列表 + 分类 + 搜索）
- 在 Discuss/Committee 完成时自动保存
- 复用现有 `ResponseCard` / `SummaryCard` 组件风格

**预估工作量**：3-5 天 MVP

### 最大亮点：#9 共识 + #1 沉淀 的组合

**"多AI共创 → 自动沉淀为知识卡片 → 逐步构建个人认知书"** — 这个闭环目前无竞品做到。

从"工具"变成"资产"的叙事本身就是差异化壁垒。

### 爆款潜力：#6 灵感触发 + #7 AI伙伴讨论

- 降低冷启动门槛（不知道聊什么也能用）
- 高度适合手机碎片时间（5 分钟探索一个话题）
- 天然适合分享（截图转发有趣的多 AI 观点）
- 注意：外部 API 会引入后端依赖，MVP 建议用本地随机问题库

## 建议 MVP 路径

```
Week 1-2: #1 知识资产沉淀（在已有 Discuss/Committee 产出上加持久化层）
Week 2-3: #2 成果打卡 + #8 场景预设入口（轻量，与知识卡片联动）
Week 3-4: #6 灵感触发（本地题库版 MVP）
```

4 周后完整叙事：**打开 App → 灵感触发 → 多AI共创 → 知识沉淀 → 打卡回顾**

## 技术约束备忘

- 所有数据存 IndexedDB，不依赖后端
- 灵感触发 MVP 用内置题库（JSON），避免外部 API 依赖
- 社交共创需要 WebSocket/共享链接基础设施，与"无后端"冲突，建议 P2
- Capacitor iOS 已有基础适配，Chat/Discuss/Advisors 三个 Tab 在手机端可用
- 桌面端 Workbench（PTY 终端）保持桌面专属，不影响手机端

## TestFlight 使用指南

### TestFlight 概述与限制

TestFlight 是 Apple 官方的 beta 测试分发平台，内置于 App Store Connect。开发者无需额外安装第三方工具即可向测试用户分发 App。

**核心能力**：

| 能力 | 说明 |
|------|------|
| 内部测试 | 团队成员（App Store Connect 团队中 100 人）即时安装，无需审核 |
| 外部测试 | 最多 10,000 名外部测试员，需通过 Beta App Review |
| 群组管理 | 按群组分发不同构建版本，支持 A/B 测试 |
| 公开链接 | 生成分享链接，扫码即可安装 |
| 反馈收集 | 测试员可直接在 TestFlight App 中提交截图+反馈 |
| 崩溃日志 | 自动收集崩溃报告，在 App Store Connect 查看 |

**限制清单**：

| 限制项 | 详情 |
|--------|------|
| 构建有效期 | 内部测试构建 90 天过期，外部测试构建 30 天过期 |
| 最大测试人数 | 内部 100 人，外部 10,000 人 |
| 测试 App 数量 | 每个 App 最多同时测试 10 个构建版本 |
| 外部测试最低审核 | 首次提交构建需通过 Beta App Review（通常 24-48 小时） |
| 安装设备限制 | 每台设备最多安装 10 个活跃的 TestFlight App |
| iOS 最低版本 | TestFlight App 要求 iOS 13+，被测 App 取决于其自身最低部署版本 |
| 加急审核 | Beta App Review 不支持加急，需提前规划时间线 |

> **SparkRing 适用提示**：作为 Capacitor + Web 的混合 App，TestFlight 测试时需特别注意 WebView 性能表现、相机/定位等原生权限在真机上的行为。

### 内部测试流程

内部测试面向团队成员，无需经过 Beta App Review，上传构建后可立即安装。

#### 1. 添加内部测试员

```
App Store Connect → 用户和访问 → 团队成员（或使用"测试员"角色添加）
```

- 内部测试员必须是 App Store Connect 团队的成员
- 团队最多 100 个内部测试员席位
- 角色：Admin、App Manager、Developer、Marketing 均可参与内部测试

#### 2. 上传构建并分发

```
Xcode Archive → Organizer → Distribute App → App Store Connect
```

上传后，在 App Store Connect 中操作：

1. 进入 **我的 App → SparkRing → TestFlight**
2. 等待构建处理完成（通常 5-15 分钟，状态变为"准备测试"）
3. 在构建版本旁点击 **分发至内部测试**
4. 可选：勾选"自动通知"让测试员收到邮件/推送

#### 3. 测试员安装

1. 测试员在 iPhone 上安装 **TestFlight App**（App Store 下载）
2. 通过邮件邀请链接或 App Store Connect 的测试邀请码进入
3. 点击"接受"后即可安装测试版本
4. 测试员看到两个版本：TestFlight 版本 + App Store 正式版（独立安装，互不覆盖）

#### 4. 内部测试的快速迭代技巧

- **多次构建同版本号**：修改 Build Number（如 0.3.4 Build 1 → Build 2），TestFlight 会提示更新
- **跳过通知批量测试**：取消"自动通知"，手动通知特定测试员
- **调试构建**：内部测试可包含 Debug 符号（dSYM），便于崩溃分析
- **快速回退**：随时在 TestFlight 面板中将某个构建版本设为"停止测试"

### 外部测试流程

外部测试面向非团队成员，需通过 Apple 的 Beta App Review 审核。

#### 1. 前置条件

| 条件 | 说明 |
|------|------|
| Beta App Review | 首次提交外部测试的构建需通过审核 |
| 隐私政策 URL | App 的隐私政策链接（必填） |
| App 描述 | 外部测试需要填写 App 描述信息 |
| 联系信息 | 提供测试支持联系方式 |
| 年龄分级 | 必须完成 App 内容分级问卷 |

> **重要**：外部测试的 Beta App Review 与正式 App Store 审核是独立的。即使正式版已被拒绝，不影响 beta 审核流程。

#### 2. 提交外部测试

```
App Store Connect → 我的 App → SparkRing → TestFlight → 外部测试
```

1. 点击 **新建群组**，设置群组名称（如 "v0.3.4 Beta"、"核心用户组"）
2. 选择要分发的构建版本
3. 填写测试信息：
   - **测试反馈邮箱**：测试员反馈将发送到此邮箱
   - **首次安装提示**：最多 4000 字符，测试员首次打开时显示
   - **更新说明**：每个版本可写更新内容，面向测试员
4. 填写 **外部测试信息**：
   - Beta App 描述
   - 隐私政策 URL
   - 联系信息
5. 提交审核

#### 3. Beta App Review

| 项目 | 详情 |
|------|------|
| 审核时长 | 通常 24-48 小时，节假日可能延长 |
| 审核标准 | 比正式审核宽松，主要检查：App 能正常启动运行、无严重崩溃、符合基本合规要求 |
| 拒绝后处理 | 修改后重新上传构建，无需重新提交审核信息（除非审核员要求） |
| 审核状态查看 | TestFlight 面板 → 外部 → 查看当前审核状态 |

**审核通过后**：可直接添加新的外部构建，无需再次审核（前提是构建差异不大）。如果新增了重大功能或权限变更，Apple 可能要求重新审核。

#### 4. 添加外部测试员

**方式 A：通过邮箱邀请**

```
TestFlight → 外部 → [群组名] → 测试员 → + 添加
```

- 输入邮箱地址，支持批量添加（逗号分隔）
- 测试员收到邮件邀请 → 打开链接 → 安装 TestFlight → 安装 App

**方式 B：通过公开链接**

生成公开链接后，任何人点击链接即可申请加入测试（详见"公开链接分发"章节）

**方式 C：通过 TestFlight 公开链接二维码**

将公开链接生成二维码，在线下场景或社群中分享。

### 群组管理

TestFlight 群组允许你将测试员分组，并向不同群组分发不同构建版本。

#### 创建群组

```
App Store Connect → SparkRing → TestFlight → 外部 → 新建群组
```

| 设置项 | 说明 |
|--------|------|
| 群组名称 | 如 "内测 Alpha"、"公测 Beta"、"VIP 用户" |
| 分发构建 | 选择要分发到该群组的构建版本 |
| 测试员数量上限 | 最多 10,000 人（所有群组共享） |

#### 群组策略建议

| 群组 | 用途 | 建议构建 |
|------|------|----------|
| Alpha（内部） | 开发团队日常验证 | 最新 Debug 构建 |
| Beta（核心用户） | 早期功能验证，10-50 人 | 经基本测试的 Release 构建 |
| Preview（公测） | 大范围验证，500+ 人 | 经过 Alpha/Beta 验证的稳定构建 |
| Canary | 新版本前置验证 | 下个版本的预发布构建 |

#### 群组操作

- **更换构建**：群组中可随时切换到新构建，测试员收到更新通知
- **停止测试**：停止某个群组的测试，测试员无法继续使用（已安装的 App 会过期）
- **移除测试员**：可从群组中移除单个测试员
- **查看安装状态**：查看每个测试员是否已安装、是否在用最新版本

### Beta App Review

Beta App Review 是外部测试的必经环节，了解其细节可大幅减少被拒概率。

#### 审核前自查清单

- [ ] App 能正常启动，无白屏/闪退
- [ ] 所有核心功能可用（SparkRing：模型切换、对话、设置）
- [ ] 隐私政策 URL 可访问且内容完整
- [ ] 如涉及网络请求，确保非本地 API 也有回退处理
- [ ] 无硬编码的测试账号或占位内容
- [ ] App 截图与实际界面一致
- [ ] Info.plist 中声明的权限都有实际使用（相机、定位等）
- [ ] 无使用私有 API

#### 常见拒绝原因

| 原因 | 说明 | 解决方案 |
|------|------|----------|
| App 崩溃 | Beta 构建存在未处理的崩溃 | 上传前完整测试关键路径 |
| 启动失败 | App 无法完成初始化 | 检查网络依赖、API Key 配置 |
| 功能缺失 | 主要功能不可用或为占位符 | 确保所有已声明的功能真实可用 |
| 隐私政策缺失 | 未提供隐私政策 URL 或无法访问 | 准备可访问的隐私政策页面 |
| 权限滥用 | 声明了不必要的设备权限 | 只保留实际使用的权限 |
| UI 问题 | 界面显示异常或布局错乱 | 在多种设备尺寸上验证 |

#### 审核加速建议

1. **提前准备**：在正式提审前完成所有自查项
2. **审核时间规划**：避免周五/周末提交（审核员较少）
3. **构建质量**：确保使用 Release 配置构建，不包含 Debug 代码
4. **快速迭代**：如果被拒绝，尽快修复并重新上传，通常第二次审核更快

### 构建版本管理

#### 构建版本生命周期

```
上传 → 处理中 → 准备测试 → 分发 → 活跃测试 → 停止/过期
```

| 阶段 | 持续时间 | 说明 |
|------|----------|------|
| 处理中 | 5-15 分钟 | Apple 服务器处理构建 |
| 准备测试 | 处理完成后 | 构建可用，可开始分发 |
| 活跃测试 | 30 天（外部）/ 90 天（内部） | 测试员可安装和使用 |
| 过期 | 超过有效期 | 构建无法安装，测试员收到过期通知 |

#### 构建版本过期处理

**过期前 7 天**：测试员会收到"即将过期"通知。

**解决方案**：

1. **上传新构建**：保持版本号不变，增加 Build Number
2. **TestFlight 会自动提示**测试员更新到新版本
3. **设置自动通知**：确保测试员能及时收到更新提醒

#### 构建版本替换

如果发现已分发的构建有严重问题：

1. 在 TestFlight 面板中找到该构建
2. 点击 **停止测试** → 该构建立即失效
3. 上传修复后的新构建
4. 将新构建分发到对应群组
5. 测试员会收到"有新版本可用"的提示

> **注意**：停止测试后，已安装该版本的用户将无法继续打开 App。因此非紧急情况建议先分发新版本，等测试员迁移后再停止旧版本。

#### 构建版本管理最佳实践

- **保留历史版本**：不要急于删除旧构建，方便回溯问题
- **清晰的 Build 命名**：在 Build Notes 中记录每次构建的变更内容
- **定期清理**：超过 90 天的过期构建可删除以保持面板整洁
- **版本号规范**：遵循语义化版本号（Semantic Versioning），Build Number 递增

### 公开链接分发

公开链接（Public Link）是最简单的外部测试分发方式，无需逐个添加邮箱。

#### 创建公开链接

```
App Store Connect → SparkRing → TestFlight → 外部 → [群组名] → 公开链接
```

1. 选择要分发的群组
2. 点击 **启用公开链接**
3. 设置链接限制（可选）：
   - **总安装量上限**：限制总安装次数
   - **有效期限**：设置链接过期日期
4. 复制链接：格式为 `https://testflight.apple.com/join/XXXXXXXX`

#### 公开链接管理

| 操作 | 说明 |
|------|------|
| 暂停 | 暂停分发，已有用户不受影响 |
| 恢复 | 重新启用暂停的链接 |
| 撤销 | 永久停用链接，新用户无法加入 |
| 更换构建 | 修改链接指向的构建版本，已安装用户收到更新通知 |

#### 分享渠道建议

| 渠道 | 适用场景 |
|------|----------|
| 二维码 | 线下活动、文档嵌入、打印物料 |
| 微信/社群 | 直接粘贴链接 |
| 官网 | 嵌入"加入测试"按钮 |
| GitHub README | 开源项目的 beta 测试入口 |
| 邮件签名 | 开发者个人推广 |

#### 生成二维码

```bash
# 使用 qrencode（macOS 可通过 brew 安装）
brew install qrencode
qrencode -o testflight-qr.png "https://testflight.apple.com/join/XXXXXXXX"
```

### 常见 TestFlight 问题排查

#### Q1: 构建上传后迟迟不显示"准备测试"

**可能原因**：
- Apple 服务器处理延迟（通常 15-30 分钟）
- 构建包含无效签名或缺少必要元数据
- 邮件中收到 Apple 的处理失败通知

**排查步骤**：
```bash
# 查看邮件通知（检查是否有 "Your app failed to process" 邮件）
# 检查 Xcode Organizer 中的上传状态
# 如果超过 1 小时仍无状态更新，重新上传
```

#### Q2: 测试员看不到新构建版本

**可能原因**：
- 测试员未更新 TestFlight App
- 新构建未被分发到测试员所在的群组
- TestFlight 缓存问题

**解决步骤**：
1. 让测试员关闭 TestFlight App 后重新打开
2. 确认构建已分发到正确的群组
3. 在 App Store Connect 中手动发送测试通知

#### Q3: 安装 TestFlight 版本后闪退

**常见原因**：
- 构建签名与 TestFlight 环境不匹配
- WebView 初始化失败（Capacitor 项目常见）
- 网络请求超时导致 App 崩溃

**排查步骤**：
```bash
# 1. 检查设备日志
xcrun devicectl device info log show --device <DEVICE_UUID>

# 2. 查看 TestFlight 崩溃报告
# App Store Connect → 我的 App → SparkRing → TestFlight → 崩溃

# 3. 确认构建使用正确的 Provisioning Profile
# Xcode → Signing & Capabilities → 确认使用 "Automatic" 或正确的手动 Profile
```

#### Q4: "此构建已过期"

**原因**：构建超过有效期（内部 90 天，外部 30 天）。

**解决**：上传新构建并分发，测试员更新即可。建议设置日历提醒在过期前 7 天上传新版本。

#### Q5: Beta App Review 被拒

**通用处理流程**：

1. 阅读 Apple 的拒绝邮件，理解具体原因
2. 在 App Store Connect 的 Resolution Center 回复并说明修复方案
3. 修复问题后上传新构建
4. 重新提交审核（通常无需重新填写审核信息）
5. 如果拒绝原因不合理，可在 Resolution Center 进行申诉

#### Q6: Capacitor/Web 混合 App 在 TestFlight 中白屏

**这是 SparkRing 这类项目的常见问题**。

**排查**：
1. 检查 `capacitor.config.ts` 中的 `server.url` 是否为空（应为空，使用本地打包）
2. 确认 `npm run build` 已执行且 `dist` 目录有内容
3. 确认 `npm run cap sync` 已执行
4. 检查 CSP（Content Security Policy）是否过于严格

```bash
# 重新同步并构建
cd apps/web-v2
npm run build
npm run cap sync
# 重新 Archive 并上传
```

#### Q7: TestFlight 反馈功能如何使用

测试员使用流程：
1. 打开 TestFlight App
2. 进入 SparkRing 测试版
3. 点击"发送 Beta 版反馈"
4. 可附加截图、屏幕录制
5. 反馈会发送到你在 App Store Connect 中配置的邮箱

开发者查看反馈：
```
App Store Connect → 我的 App → SparkRing → TestFlight → 反馈
```

#### Q8: 如何查看 TestFlight 安装统计

```
App Store Connect → 我的 App → SparkRing → TestFlight → 概览
```

可查看：
- 总安装数
- 活跃测试员数
- 每个构建版本的安装和会话数据
- 崩溃率对比

# 自愿体验反馈

当前状态：客户端邀请、表单与本地提交适配已实现；公网接收端尚未配置和验证，默认不开启入口或邀请。不能把本地测试回执当作维护者实际收到了反馈。此功能无需填写者账号。

## 邀请规则

从升级到带此功能的版本以后开始计数，不扫描历史对话。只有被本地服务接受的 Pilot 首条/后续请求、Bot 直派/自动分流/追问才计数。定时任务、peer 分发、打开页面、轮询、工具调用和重复 requestId 不计数。

同时满足以下条件才有资格：

- 至少 3 个 UTC 使用日，首次使用已过去 72 小时。
- 至少 6 次使用：与前次主动请求相隔至少 30 分钟才算新一次。
- 至少 12 次主动请求，最后一次已过去 60 秒。
- 公网接收地址已配置；本机所有会话和 Bot 均没有正在执行/等待处理的任务。
- 页面在前台，30 秒内未键盘输入或点击，当前无未发送的输入、弹窗、设置、引导或更新操作。

显示一条内联邀请，绝不自动打开表单、不抢焦点、不发送桌面通知。所有标签页共享原子领取状态，刷新和版本升级不重置。

首轮最多邀请两次。第一次显示即记为已邀请；只有明确选择「以后再说」才允许 14 天后的第二次。第二次之后不再邀请。关闭页面、主动打开表单、选择「不再提醒」或成功提交后均不再自动邀请。常驻手动反馈入口不受邀请频次限制。

`feedback-state.json` 位于本地 Pilot state root。只保存计数、日期、散列后的去重标识及提醒偏好；不会外传这些计数，不保存聊天内容。损坏的状态默认停止自动邀请。更换 state root 或重新安装且清除 state root 不属于同一安装。

## 提交内容

必填：使用入口（Pilot / Bot / 两者）、使用场景、完成情况。选填：需要自己接手的部分/有用的地方、希望 Bot 长期负责的事情、联系方式。

外发字段严格限定为：`requestId`（本次反馈随机回执标识）、`surface`、`job`、`outcome`、`detail`、`recurring`、`contact`、`campaign`、`version`、`system`。不附带对话、代码、文件/工作区路径、provider/模型、账号或 Key。用户手写的回答仍可能包含私密内容，发送前明确提醒。未填写联系方式时，维护者无法私下联系该用户。

只有显式点击发送才发起公网请求。超时、重定向、无有效回执等均不显示成功；答案保留在当前窗口，可用相同 requestId 重试，接收端必须幂等。提交过程不持有应用的 mutation lock，不阻塞发送/停止工作任务。

## 接收端合同与启用条件

`MMS_FEEDBACK_ENDPOINT` 是维护者部署的 HTTPS intake URL，仅供服务器运行环境配置；禁止客户端传入任意 URL。客户端不携带维护者的飞书/GitHub/邮箱凭据。标准发行的 `DEFAULT_ENDPOINT` 保持空值，直到维护者确认接收位置并完成真实送达验证。

接收端接收上述 JSON，持久保存成功之后才返回：

```json
{"received": true, "receiptId": "与请求 requestId 相同"}
```

公网接收端必须校验字段和长度、对 requestId 去重、限制频率和请求体积，将数据放在维护者私有收件箱。飞书或邮箱凭据只保存在接收端，不能嵌入 MMS。任何通知失败都不得丢失已收集反馈；只有确实持久收到才能发回执。

启用前真实验证：未登录用户提交 → 私有目的地新增一条 → 重试无重复 → 附带字段与 UI 披露一致 → 接收不可用时前端保留答案。公网目的地未落实时，功能保持关闭，不启动面向用户的收集。

反馈只能解释愿意回复者的经历，不能代表全体活跃用户或流失率；它不提供远程使用遥测。

# v5.0.5 · 计划里给某一步指定的模型,现在真的会用上

## 升级须知

5.x 是预览线,Bot 工作台仍在打磨。这一版只有一个迭代点,没有新的配置项,不清空配置或会话历史。

## 修复

**计划里给某一步指定模型,以前对跑过任务的 Bot 是无效的,而且不报错。**

Bot 协作的计划可以给某个步骤单独指定模型("这一步用 glm-5.3 跑")。这个指定会被算出来,但启动时如果复用了 Bot 已有的会话,算好的模型就被整个丢掉了 —— 那一步实际用 Bot 的默认模型跑完,界面上没有任何提示。只有从未启动过的全新 Bot 才碰巧能用上。

现在它真的生效了,而且**不会弄脏 Bot 的主对话**:被指定模型的那一步跑在自己的一次性会话里,跑完就收走;Bot 的主会话仍然是原来那个,之后的普通轮次继续用 Bot 自己的模型、接着原来的历史。

顺带补上了一道更根本的防御:**启动时如果发现要用的模型和被复用会话当初启动时的模型不一样,就不再复用那个会话了。** 以前这种不一致是被静默吞掉的 —— 这正是上面那个 bug 的成因。

## 已知边界

上面那道防御有一个用户可能撞到的副作用:如果你在 Pilot 的会话页里**直接给 Bot 的主会话换了模型**,而 Bot 自己的默认模型没跟着改,那么下一轮 Bot 任务会因为"模型对不上"起一个新会话 —— 之前的对话历史不会带过去,而且**目前这一步没有提示**。

要避免的话,改 Bot 的模型请走 Bot 自己的设定(或者在对话里说"换成 X"),而不是在会话页上改。提示会在后续版本补上。

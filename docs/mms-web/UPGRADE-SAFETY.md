# 升级与会话保护

## 当前能力（v4.6.0）

**会话可恢复不等于进程不中断。** 关闭浏览器只关页面；停止或重启 Pilot 服务会关闭它启动的 Pi 子进程。重启后会话状态如实显示已停止，下一次发送读取保存的运行快照和原生历史，再启动新的 Pi 进程继续。

私有验证已覆盖：相同自定义 state-root，v4.5 服务退出后用新代码启动，同一会话 ID 与历史事件保留，继续发送成功，真实 Pi 请求包含旧历史。没有把模型的自述当作恢复依据。这个验证没有证明正在运行的工具、审批、排队消息能跨重启继续执行：旧排队消息会取消，未完成审批不会自动重放。

手动更新前应等当前轮次结束，处理等待确认的任务；备份并保留原数据目录、配置目录和项目路径。`sessions/` 只是展示记录，`runtimes/` 还包含恢复使用的 `resume.json` 和 `conversation.jsonl`，不能删除。相同配置文件不代表相同会话目录；遗漏自定义 `--state-root` 会看到另一份会话列表。

当前尚未提供自动升级。现有运行方式也不提供跨版本原进程保持运行的承诺。不能因为安装命令执行成功就声称会话保护已验证。

## 自动升级进入产品前必须满足

以下是后续实现要求，**不是已经实现的功能**：

- 运行中、等待确认或有排队消息时延后重启；进入更新后禁止新任务进入，避免检查后又开始运行的竞态。
- 固定目标版本，在独立版本目录完成安装与校验；不能原地覆盖正在使用的代码和依赖。
- 保存并传递原 state-root、config-root、端口和安装身份；验证恢复的是同一组会话，不能只检查 HTTP 200。
- 保留旧版本和数据备份；新版本启动或历史恢复失败时能返回旧版本。
- 验证长对话、文件引用、模型切换、已停止/异常会话、排队与审批、重启后继续发送。
- 若要求运行中的 Pi 进程也完全不中断，需要先将会话运行服务与可替换的 Web/安装进程解耦，再验证跨版本连接与事件回放；仅保留 PID 或隐藏“已停止”状态不算实现。

# 升级与会话保护

## v4.9 的更新方式

? 旁的「更新」提供版本、更新内容、手动检查和一键安全更新。默认每 6 小时检查最新稳定 Release，可以关闭。检查不调用模型、不安装软件、不覆盖模型配置。新版准备好后由使用者决定是否更新。

- **默认保留 Pi 进程**。有执行中、压缩上下文、待确认、排队消息、未返回请求或无法确认的状态时等待；空闲 Pi 也保持连接。等待期间可以继续工作或取消更新。
- **可明确勾选「允许重启空闲会话」**。仅在所有任务安全空闲且原生历史可恢复后，先备份，再请求空闲 Pi 正常退出。没有强制 kill 升级路径；进程未按时退出就停止更新。运行/审批/队列即使勾选也等待。
- **同一会话继续聊**。重启后保留会话 ID、历史、运行目录、附件与工作文件夹；下一条消息从原生 Pi 历史恢复。浏览器草稿不会因更新被自动刷新清空。

**会话可恢复不等于原进程永久存活。** 允许重启空闲会话会更换 Pi PID。运行中的工具、审批和排队消息不跨进程重放，因此更新必须先等待它们完成；不能把保留历史说成无中断执行。

## 更新会换掉什么

页面里的更新和 `install.sh` 现在都替换整套安装，不只是网页服务：

- 验证新版能启动并正常应答之后，同一份代码会写进当前安装目录，`mms`、`mmf` 和 Pilot 从此是同一个版本。写入前逐项备份，任何一步失败就整体还原到更新前的版本，网页仍按暂存副本运行。
- 源码检出不会被写。开发机上运行的是 git 工作树，更新只换网页服务，确认页会写明原因。
- 端口不变。更新在原端口重新启动，页面在检测到版本变化后自动刷新；`install.sh` 也会先记住正在运行的 Pilot 的端口，装完回到同一个端口。
- `install.sh` 会清掉上一次页面更新留下的暂存版本指针，避免重装之后网页端看起来毫无变化。

确认更新之前，页面会先给出这次更新的实际影响：更新后的地址和端口、命令行是否一起更新、是否重启空闲会话，以及该版本发布说明里 `## 升级须知` 一节的原文。发布说明没有这一节，就表示这个版本没有需要提前知道的代价。

## 更新事务

1. 固定官方稳定 tag，在私有 `updates/versions` 下载源码、核验版本及静态资源摘要，并用临时配置试启动。拒绝跳转、目录逃逸、不受支持的符号链接和超限包；不会执行安装器、升级全局依赖或原地覆盖正在使用的源代码。
2. 持有操作锁并重新检查安全状态。切换窗口暂不接受新任务，防止检查后又开始运行。完整备份 Web state，包含 sessions、runtimes、附件、独立配置、项目资料与工作目录记录；检查空间与备份前后的文件摘要。
3. 新服务使用原端口、state-root、config-root 与工作目录。处于验证阶段时拒绝会话操作；核对源码身份、版本、每个会话、恢复路径与旧事件后才恢复发送。
4. 新服务无法启动或验证失败时返回旧版本并恢复备份。候选产生的数据与旧代码保留；若提交响应丢失，不终止可能已经接收工作的新版服务，而是提示重新连接核实。
5. 成功后保存私有活动版本标记，正常入口继续使用新版。页面显示「刷新使用新版本」。

## 手动安装与旧版本

日常安装命令：

```bash
curl -fsSL https://raw.githubusercontent.com/CtriXin/multi-model-switch/main/install.sh | bash
```

新版安装器检测到目标安装目录正被 Pilot 使用时停止，并引导到页面更新入口；不会关闭进程、删除历史或覆盖正在使用的依赖。运行时与安装器互斥锁也防止检查后同时启动的竞态。v4.9 之前的进程额外按实际启动路径/工作目录检查；首次从旧版迁移时，若旧页面没有更新入口，需完成任务并自行退出旧服务，再重跑安装命令。

已经下载到本地的旧安装脚本不具备新保护；请使用上面的当前入口。外部强制结束进程、手动删除目录、直接 git 覆盖运行源码不属于更新事务。

会话数据在启动时选定的 Web state-root；`sessions/` 是展示记录，`runtimes/` 还包含 `resume.json` 和 `conversation.jsonl`，两者都必须保留。自定义启动需继续使用原 `--state-root`。模型 API Key 与人工覆盖值不会被后台更新检查写回。

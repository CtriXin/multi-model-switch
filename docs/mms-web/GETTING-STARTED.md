# MMS Pilot 4.6：安装、配置与日常使用

MMS Pilot 把 MMF 日常使用的模型、通道、effort、工作文件夹和 Pi 会话放进浏览器。AI 仍通过 MMS 原有启动器在本机执行；浏览器是交互入口。v4 首版的实际 Web harness 是 Pi，Claude、Codex、OpenCode 的 CLI 启动能力仍在 MMS 中，暂未成为 Web 会话。

## 安装

支持 macOS、Linux。Windows 暂建议在 WSL2 内运行服务；Windows 原生安装与系统文件选择尚未验收。

安装程序会准备 Python 3.11+、兼容的 Node.js 和 Pi，已有 CLI 保留，缺失的 Claude/Codex/OpenCode 会自动补装。发布包自带编译好的页面，使用者不需要构建 Web。

复制这一条命令到终端：

```bash
curl -fsSL https://raw.githubusercontent.com/CtriXin/multi-model-switch/v4.4.0/install.sh | bash
```

这份稳定版安装入口默认获取最新 stable Release，重复执行可升级。安装过程默认中文，自动设置命令 PATH；完成后只问一次是否打开 MMS Web，同意后在后台启动。没有交互终端时打印打开命令；`--launch-web` 可直接打开，`--no-launch-web` 可禁止打开。已有相同安装、版本和配置空间的 Web 会被复用，其他实例保留并使用新端口。

之后随时运行 `mms web --open`；当前终端找不到命令时用 `~/.local/bin/mms web --open`。Web 默认使用自己的配置空间，直接在设置里连接服务即可。高级用户仍可显式指定已有 MMF 配置目录。

字体安装提供 Fira Code 和 JetBrains Mono，失败不会影响 MMS，`--no-coding-fonts` 可关闭。退休可选包不再安装；可确认 MMS 来源的旧入口会备份移走，自定义同名内容、全局 hooks/MCP 设置与真实配置保留。

macOS 也可以在 Finder 打开 `~/.mms/MMS Pilot.command`。如果从 Finder 启动时找不到通过 shell 管理器安装的 Node/Pi，先从能运行 `pi` 的终端启动上面的命令。系统文件选择器的交互与 macOS 本机权限有关。

独立命令 `mms-web --open` 与 `mms web --open` 都可打开 Web。终端中按 Ctrl+C 停止服务；浏览器关闭只关闭页面。服务重启后，对话保留，继续发送时会恢复 Pi 会话。

## 第一次配置

没有可用通道时先完成连接，配置成功后才显示聊天功能教程。空白安装会直接打开连接向导；已有通道暂时不可用时，打开设置查看原因，不要求重新创建账号。

1. **填服务地址**：粘贴服务商提供的完整 API 地址。名称自动生成；服务商要求其他接口时，再展开可选设置选择协议。
2. **填连接密钥**：粘贴自己的 API Key，点击「连接并读取模型」。Key 不是 MMS 提供的免费额度。连接失败留在这一步修正，返回修改也会保留当前输入。
3. **选一个模型**：勾选一个熟悉的模型就可以开始，之后可以再添加。只有一个模型时自动选中；服务不提供列表时可手动填写真实模型 ID。
4. **确认并载入预设**：检查保存内容后点击「保存并载入预设」。MMS 随版本提供的模型能力会随配置发布，页面再读取当前通道实际采用的预设。首次无需手动填写 effort、上下文或识图参数；已有本地覆盖优先级不变。
5. **开始第一条对话**：预设读取完成后点「开始使用」，再进入悬浮教程。已选好工作文件夹，普通聊天可以直接继续；教程中的示例先填进草稿，自己点击发送后才调用模型。

没有服务信息时可以「稍后配置」，随时从首页或 ? 回到连接流程。API Key 不存入浏览器；关闭未保存向导会清理临时预览。读取模型列表不代表已验证生成能力；实际对话使用服务额度。

模型名相同时，先选模型，再比较通道。收藏、通道备注和首选通道用于快速选择。实际运行参数以 MMS 发布的模型能力和所选通道为准，不能单凭模型名字判断图片、上下文或 reasoning 能力。

独立 Web 配置和已批准的 MMF Registry 都可在模型管理中维护可见模型与长期默认 effort。保存前会显示具体差异；独立配置保存在自己的 Web 数据目录，使用相同的 Registry 校验与发布流程。旧独立配置首次保存时会保留其全部通道，之后以已批准目录作为模型与连接来源。模型默认值可能由多条通道共用，保存前会列出受影响通道。新会话及切换模型时采用这些默认值；当前会话的 effort 也可单独调整。

普通 `mms web` 默认在独立 Web 数据目录中配置，不需要先做 CLI 配置。高级 `mms config web` 仍保留，负责 Web 尚未覆盖的 Registry、账号、协议等完整配置。

## 已经在使用 MMF

`mmf` 指向开发工作树，`mmd` 指向 stable，`mmg` 指向 canary，`mmm` 指向 main，`mms` 是公开安装副本。这些命令的通道意义没有改变。只有包含 v4 代码的工作树才能运行新的 `web` 子命令。

如果对应的 MMF 工作树已经更新到 v4：

```bash
mmf web --open
```

它会使用该 launcher 选定且已存在的 `MMS_CONFIG_ROOT`。独立安装的 Web 要使用明确的已有配置时，可运行：

```bash
mms web --config-root "$HOME/.config/mms-next" --open
```

运行时配置会复制到各会话的私有目录。切换模型、聊天、调整本次 effort 不会改写源配置。设置页中明确确认的模型/通道保存才会更新用户选择的配置源。

不要把运行目录设成 MMS 配置根目录。已有用户应保留原配置备份；升级程序与 Web 都不会要求把 Key 发给项目维护者。

## 日常操作

- 工作文件夹：点击新会话顶部的文件夹，输入项目名查找已添加的项目；检测到 zoxide 时，也会利用它的常用目录记录。可以直接按 Enter 选中，或浏览其他文件夹、粘贴完整路径。Pilot 记住上次选择；没有 zoxide 也可正常使用，无需安装额外依赖。AI 会在这个目录工作，这不代表操作系统级 sandbox。
- 本地文件：拖拽、粘贴截图、通过 + 选择文件或粘贴带引号的绝对路径，引用插入正文光标处。可以在不同文件之间写各自的要求；删除正文路径即取消本轮引用。`@` 仍可引用工作目录文件。原路径引用只传路径，不受上传大小限制；原文件移动或删除后，需要重新引用。
- 没有原路径的文件：浏览器通常只提供文件内容。Pilot 自动保存到当前项目 `.pilot/attachments`，单个文件最大 8 MB；文件名独立生成，不覆盖同名文件。插入的路径可在该项目的其他会话继续引用。取消引用或清空草稿不会删除已保存文件，分享项目时也请留意这个目录。图片由 Pi 的读取工具或识图辅助处理。
- 模型切换：在输入框右下角打开当前会话设置，选择模型与通道。同通道可原生切换；不同通道通过新私有进程延续原会话。保留历史，下一条消息采用新选择。正在执行或等待确认时，先完成/停止本轮再切换。
- effort：选择所选模型真实支持的级别；「默认」来自 MMS 已配置的默认值。不同模型可用级别不同。
- Skills 与命令：添加 Skills，使用 `/` 打开命令提示，`@` 查找文件。只展示当前接入支持的命令与交互。
- 过程与结果：工具按组展示，支持展开参数和输出；最后回答保留在外面。每轮可收起/展开过程，底部可收起/展开全部。设置 → 外观与使用 →「完成后自动收起过程」控制默认行为，设置保存在当前浏览器。
- 状态：运行中、思考、工具执行、等待回答、错误、本轮完成分别显示。完成提示和未读高亮帮助你发现新结果。
- 长对话：右侧提问导航 hover 展开，点击回到自己的某次提问；离开底部后可返回最新消息。复制等次要操作在 hover/键盘聚焦时出现，触屏上可直接操作。
- 成果与历史：查看 Markdown、文本、CSV 表格、图片和静态 HTML；选择已记录版本、比较差异或下载。原文件变化/删除会明确提示。会话继续支持搜索、重命名、归档、导出和分支。
- 工作方式：「只读规划」限制当前提供给 Pi 的工具；「执行任务」允许实际改文件和运行命令。仍需理解任务将操作哪些本地文件。

## 别人怎么使用

推荐把 GitHub Release 和本文发给对方。对方在自己的电脑安装、启动、填写自己的 Key；他的文件、配置和会话保留在他的电脑。

默认地址是 `http://127.0.0.1:8765`，只在运行服务的本机可访问。把这个地址发给别人，他们打开的是自己的电脑，不是你的服务。v4 没有多用户账号、远程访问认证、团队权限和公网部署能力，不提供公网 `--host 0.0.0.0`。

若只是分享工作方法，用「保存为任务模板」导出模板，对方导入后补自己的模型和文件。模板不是 Key/账号搬家工具，也不是自动打包所有 Skills 的插件安装包。分享示例材料前仍应自行检查业务信息。

## 数据、更新与故障

默认 Web 数据在 `~/.local/share/mms-web`（设置 `XDG_DATA_HOME` 时遵循该路径）。其中包含 Web 配置、会话、私有运行快照、无原路径的图片等敏感本地数据，不要整体发到 GitHub。启动参数 `--state-root` 可选另一个独立数据目录。

升级前先等正在执行的任务完成，并处理等待确认的任务，再按该版本安装说明更新。数据目录与安装目录分开，但目前服务重启会结束它启动的 Pi 进程，尚不支持执行中无缝升级。重启后历史可打开，继续发送会用保存的上下文启动新的 Pi 进程。

必须保留原 `--state-root`、`--config-root`（如果指定过），以及整个数据目录中的 `sessions/`、`runtimes/` 和项目文件；不要只备份聊天列表。`runtimes/` 包含继续会话需要的运行快照与原生记录。手动改目录不会自动搬迁旧会话。更新前备份数据；当前不提供自动升级按钮，详情见[升级与会话保护](UPGRADE-SAFETY.md)。v3 没有 Web，不能用 v3 打开 v4 会话界面。

| 现象 | 处理 |
|---|---|
| 浏览器无法连接 | 确认服务终端仍在运行；查看它打印的本机地址 |
| 8765 已被占用 | 使用 `mms web --port 8767 --open` |
| 提示 Pi/Node 不可用 | 在启动 Web 的同一终端验证 `pi --version` 与 `node --version`，安装兼容版本 |
| 模型拉取为空/失败 | 检查 Base URL、Key、协议与服务是否支持模型列表；可手动配置已确认的模型 ID |
| 同名模型走错通道 | 查看输入框展示的通道名，在模型弹窗明确选择目标通道 |
| 切换失败 | Web 会保留旧选择；检查新通道能力与凭据，不会转用全局 OAuth |
| 本地文件不存在 | 检查路径、文件是否移动、服务是否在同一台电脑 |
| 想看完整过程 | 点击展开过程，或关闭自动收起设置 |

版本边界与后续开发见 [下一阶段交接](NEXT-PHASE.md)。


### 修改成果的一部分

打开右侧「成果」，选择文件。在「原文 / 选段修改」中选中文字，再点「引用选段」；图片可以拖选区域并点「引用选区」。片段会进入当前会话输入框，写下修改要求并发送，AI 才开始处理。文件已经变化时，需要打开当前文件重新选择。

修改完成后可选择新旧版本查看差异。这里保存的是成果版本，不会自动回滚工作目录；对话分支也不等于文件回滚。旧会话没有历史快照时只能展示当前文件，首次使用本功能后的成果才开始记录版本。

HTML 是静态预览，脚本、外部资源和跳转均停用；需要原文件时使用下载。CSV 表格最多显示 200 行和 50 列，原文和下载不裁剪。每会话最多记录 40 个成果、每文件 20 个版本、共 64 MB；达到上限会提示并保留旧版本。PDF/Office 暂不提供内嵌预览，可通过工作文件路径使用本机应用打开。


### 保存项目资料、检查本次来源

在新会话或当前会话的「项目资料」里，保存项目背景、写作要求和常用约定。资料只属于当前工作文件夹；可以编辑、停用或删除。只有明确保存且启用的内容会加入这个项目之后的新消息。每个项目最多 20 条，单条最多 20 KB，总正文最多 80 KB；大文件直接引用原路径。

自己的消息下方可展开「本次使用」，检查本次加入的项目资料版本、Skills 来源与同名覆盖、附件、文件引用和成果选段。已提交表示 Pi 已接收请求，文件引用不代表模型已经读取。排队、取消、发送失败或结果待确认会单独显示；旧消息没有来源记录时不会补造。

停用或删除资料不会从已发送的会话历史撤回内容。编辑后的新版本只在后续消息生效，历史记录仍显示当时版本。保存遇到冲突时保留当前草稿，刷新列表核对后再保存。资料随 Web 数据目录保存和恢复。


左上角 Logo 旁和设置页顶部均显示当前 MMS 服务版本，便于确认升级是否生效。


### 第一次使用：跟着悬浮引导试一次

v4.6.0 起，首次没有可用通道时先打开分步连接流程，连接成功并读取模型预设后才显示悬浮教程。已有可用通道直接介绍聊天操作，跳过已完成的连接步骤。亮起的功能可以直接点击：工作文件夹 → 模型与通道 → effort → 第一条消息 → 手动发送并查看回复。工作文件夹和 effort 可保留默认值。

引导里的「帮我填入一条示例」会保留新任务已有草稿，把示例追加在后面。你可以修改它；只有自己点击发送才会调用模型。引导不会替你改模型、effort、文件或保存连接设置。打开模型选择、Skills 等真实窗口时，引导会暂时让开，关闭后恢复。

基本操作之后，可继续认识附件、Skills、项目资料、成果与版本、运行详情、会话管理和设置，也可以随时跳过。首次提示按浏览器记录，刷新不重复出现；右上角 **?** 随时打开帮助，点「重新开始悬浮引导」再走一遍，也能搜索功能说明并跳到相应控件。已有会话换模型保留上下文；换工作路径要新建会话再选择。

### 整理侧栏与调整阅读习惯

工作文件夹旁的更多菜单可复制路径、重命名、移除、排序和新建会话。移除只隐藏侧栏入口，文件及旧会话保留，旧会话仍可在「其他工作空间」继续；重新添加同一路径可恢复分组。会话菜单支持复制 Session ID、重命名、分叉、导出与归档，长列表可加载更多。

设置以弹窗打开，关闭后回到原会话。外观支持跟随系统、五种强调色、界面和等宽字体、中文字体兜底、12–20 px 字号及加粗。字号同时影响对话、设置、侧栏和引导。选择即复制默认关闭，启用后选中对话文字会覆盖剪贴板。

通道模型管理可编辑图片输入能力和上下文长度，显示事实来源，并在保存前预览影响。纯文本模型的识图辅助候选来自当前通道，热切换与恢复会同步工具状态；模型名字或正文自述均不作为能力证据。


v4.5.0 起，通道模型管理的「检查最新能力」会逐行显示差异：先勾选、填入草稿，再检查并保存。你已保存或尚未保存的手动值默认不勾；也可主动查询 OpenRouter 目录作为备选，它不会越过仓库和本地已知资料。追加查询不会重置已经做出的选择。更新模型能力数据仍需更新 MMS，当前尚未加入后台自动推送或一键升级应用。

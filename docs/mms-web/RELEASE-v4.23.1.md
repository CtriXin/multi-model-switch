# v4.23.1 · 探测模型列表的时候,Pilot 不再整个卡住

## 升级须知

稳定线的常规版本。没有新的配置项,没有数据迁移,不清空配置或会话历史。

## 修复

**填完模型服务地址点探测,或者刷新模型配置的时候,Pilot 的其他操作不再跟着排队。**

以前这两类动作握着一把全局的写锁:

- 「探测模型列表」会去请求你刚填的那个地址,最长等 **15 秒**
- 模型配置的检查 / 刷新会起一个子进程去读能力快照,最长等 **90 秒**

在那段时间里,发消息、停会话、确认更新、开关手机访问 —— 全部排在后面动不了。而地址填错、服务不回包,恰恰是这个功能最常见的使用场景:你最可能触发长时间等待的那一次,正是你最需要能取消重填的那一次。

这三件事其实一个字都不写:它们跑在一份临时快照上,前后各比对一次配置指纹,配置变了会直接报错让你重来。所以它们根本不需要那把锁。现在它们跑在锁外面,**真正写配置的预览和应用仍然锁着**。

同类问题这是第三次了 —— v4.18.0 修过文件夹搜索,v4.23.0 修过打开手机访问时的反向 DNS。这一次是审查时提前发现的,没有用户报过。

## 从这里去 5.x

打开 Pilot 的「版本与更新」,把更新通道选成 `5.x 预览版`,检查更新,确认升级。5.x 是预览线,带 Bot 工作台,还在打磨。

**注意方向性**:4.x → 5.x 可以在 Pilot 里走完;**5.x → 4.x 现在不行** —— 应用内更新只安装比当前更高的版本,所以在 5.x 上选回 `4.x 稳定版` 不会自动降级,要重跑安装器并指定 stable 通道。此前的发布说明把这条说成双向可逆,那是不准确的,已在跟进修正。

两条线在同一台机器上不能共存,但配置、通道和会话历史都在同一个 config root(`~/.config/mms-next`)里,来回切不会清空它们。

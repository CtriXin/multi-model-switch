# v4.22.2 · 手机访问不再踢掉本机窗口，降级不再漏出 Bot 会话

## 升级须知

这是 4.22.x 稳定线的常规修复版，全部改动都是行为修正，没有新的配置项、没有数据迁移、不清空会话历史。后端、npm manifests 和 Web 静态包统一为 4.22.2。

5.x 预览线（Bot 工作台）不在本版本内，仍走 dev 通道。Windows 仍为 Native Preview。

## 修复

- **打开手机访问后，本机 `127.0.0.1` 的窗口不再失效。** 以前切到局域网模式会让当前开着的页面需要重新带参数才能用。现在开关切换时会给当前连接种下凭据，本机窗口继续可用；换发令牌之后旧链接照常失效，而当前窗口仍然在线。
- **4.x ↔ 5.x 上下切换不再漏出对方的会话。** 用 5.x 建过 Bot 的机器降回 4.22 时，Bot 名下的会话会以普通聊天出现在侧栏。现在这条线只认自己的会话，别的来源既不进列表、也不能按 id 打开详情，而磁盘上的文件逐字节不动，升回 5.x 时 Bot、定时和记忆都还在。新增一条回归场景真的用 5.x 的代码写状态、再用 4.22 的服务器读它。
- **通道保存被 MMF 挡下时，说出真实原因。** 以前不论为什么被拒，都只回一句「MMF 未允许这组修改」，用户无从下手。现在会把实际的阻塞原因带到界面上。
- **项目文件夹选择弹窗打开后，光标直接落在搜索框。** 原生 `<dialog>` 的 `showModal()` 会把焦点抢到右上角关闭按钮，`autoFocus` 被冲掉；现在打开就能直接敲键盘搜索，搜索 → 上下键选择 → 回车确认全键盘可用。

## 已知边界

降级到 4.22 之后，本线拒绝按 id 查询它不认识的会话，但按 id 的写操作端点（改名、发送等）仍可达；正常使用走不到那条路径，界面上也拿不到那个 id。这条记在案，后续版本收口。

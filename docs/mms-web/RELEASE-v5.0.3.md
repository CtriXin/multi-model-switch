# v5.0.3 · 被打断的回合不再是一片空白

## 升级须知

5.x 是预览线,Bot 工作台仍在打磨。这一版只有修复,没有新的配置项,不改 Bot runtime,不清空配置或会话历史。

**从这一版起,5.x 每个迭代点各自一个版本号**,不再把一批改动攒进一个版本。所以这一版只有一件事。

## 修复

**回合被打断之后,界面会说清楚发生了什么。** 以前有三种情况会留下一片空白,用户看不出是卡住了还是结束了:

- 在模型正在回答的时候插入一条引导(steer)
- Pilot 服务在回合进行中重启
- 你自己点了停止

现在这些情况都会给一条明确的占位说明,并且那条没送出去的消息可以**一键重新发送** —— 以前它只是没了,得自己重新打一遍。

**已经停止过的历史回合不再谎报"执行被中断"。** 这是这一版真正难缠的那半:判定函数在检查"是不是最新回合"之前就先看了有没有被强制结束的工具,所以只要你在第一轮点过停止,那一轮之后就永远挂着「执行被中断」和一个「重新发送」按钮 —— 即使你早就在第二轮问了别的问题并且拿到了回答。现在只有最新的那个回合才会被评估是否中断,历史回合安静地留在原地。

## 一个已知的措辞问题

你自己点停止,和进程真的崩了,现在共用同一句「本轮执行被中断,未产生回复」。它对前一种情况偏重了 —— 你是有意停的,不是出了故障。要分开说需要后端给事件加一个标记,记在后续迭代里。

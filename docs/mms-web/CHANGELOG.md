# MMS Pilot 更新日志

每个版本的完整说明在 `docs/mms-web/RELEASE-v<版本>.md`。这份是索引和规则。

---

## 两条发布线

| 线 | 分支 | 当前版本 | 是什么 |
|---|---|---|---|
| **稳定线** | `main` | **4.23.0** | 永久维护。日常使用装这条。 |
| **预览线** | `dev` | **5.1.0** | Bot 工作台,还在打磨。是稳定线的超集。 |

两条线**不能在同一台机器上共存**,但配置、通道和会话历史都在同一个 config root(`~/.config/mms-next`)里,来回切不会清空它们。

**怎么换线**:4.22.3 起,打开 Pilot 的「版本与更新」,把更新通道选成 `5.x 预览版` 或 `4.x 稳定版`,检查更新,确认升级。选通道只改变它检查什么,升级仍然要你确认。也可以从终端重跑安装器带 `--channel dev` / `--channel stable`。

**改动的流向**:`main` 上的每一处改动都默认进入 `dev`,所以 5.x 永远是 4.x 稳定线的超集;`dev` 上稳定下来的能力会定期回流 `main`。

## 版本号规则(2026-09-17 起)

**一个迭代点 = 一个 patch 版本。** 一个功能点或一个修复点各自发一个版本,不再把一批改动攒进一个版本里。

- 纯文档改动(工作包、计划、报告)**不算**迭代点,不 bump
- 多个 PR 如果是同一个不可分的功能(后端单独上线等于给用户一个没有界面的能力),算一个迭代点、一个版本,发布说明里分节讲

**为什么改**:v5.0.0 一个版本吃掉了 19 个 merge,v5.0.2 吃掉了 15 个。攒得越粗,就越说不清"这个功能是哪一版加的"、"这个 bug 是哪一版修的"。

## 已知的记录缺口

这份日志不假装完整,以下是实际情况:

- **1.x / 2.x / 3.x 不在这份日志范围内。** 那是 Pilot Web 之前的 MMS(终端多模型切换),`docs/mms-web/` 下没有它们的发布说明。
- **4.x 里有 22 个版本发了 tag 但没写发布说明。** 主要是两段:**4.21.2–4.21.11 和 4.21.13**(Windows Native Preview 期间的密集 hotfix,内容被归纳进 4.21.12 和 4.21.14 两个"累积版"说明里),以及 **4.0.1 / 4.1.0 / 4.2.0 / 4.2.1 / 4.3.0 / 4.7.0 / 4.7.1 / 4.7.2 / 4.8.0 / 4.8.1 / 4.9.0**。
- 这正是 2026-09-17 改规则的原因之一:发得粗、或者发了不写,事后就补不回来了。从 4.22.4 / 5.0.3 起,每个迭代点都有自己的版本号和说明。

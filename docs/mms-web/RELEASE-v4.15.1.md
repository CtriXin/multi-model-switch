# v4.15.1 · 终端能跑 Pi 但 Pilot 全灰的修复

- **Pilot 不再因为找不到全局 `pi` 就把所有模型标灰**（#200）：一次真正的启动走 `scripts/pi-cli-wrapper.sh`，它接受 PATH 上的全局 `pi`、安装时预热的 npx 缓存，或现场拉取。而挡在启动前面的那道判定只看 PATH，于是一台「终端跑 `mms` 完全正常」的机器，在 Pilot 里会显示 24 个模型全部不可用。现在两边用同一套判定。
- **说清楚到底缺什么**（#200）：以前所有模型和通道只显示「Web 会话接入尚未就绪」，不指向任何动作。现在区分三种情况并各自给出要做的事：找不到 Pi（PATH 与缓存都查过）、Node 低于 22.15（Pilot 实际要求 `node:zlib` 带 zstd 支持）、安装缺少会话执行组件。
- **更新不再写进上一次更新留下的暂存副本**（#198）：在 v4.15.0 之前用页面更新过的机器，Pilot 跑的是 `<数据目录>/updates/versions/` 里的暂存副本。那不是安装目录，往里写新版会在下次重启时回落到更旧的代码。现在这种情况会被识别并拒绝，保留原有的指针方式。

## 升级须知

- 如果你的 Pilot 之前是**在页面里点更新**升上来的，建议这次改用安装命令升级，而不是再点一次页面更新。安装命令会把安装目录、命令行和 Pilot 一起换掉，并清理掉暂存副本留下的指针，之后的页面更新才会正确地同时更新命令行。
- 在你平常能正常运行 `mms` 的终端里执行安装命令。Pilot 会继承那个终端的环境，这样它找 Pi 和 Node 的条件和终端一致。
- 本次更新会替换安装目录里的 `mms`、`mmf` 和 Pilot。如果同一台机器上正有 `mms` 会话在跑，建议等它结束。

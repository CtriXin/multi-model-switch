# v5.0.4 · Bot 会按时自己醒来,也能在对话里换模型

## 升级须知

5.x 是预览线,Bot 工作台仍在打磨。这一版不改配置结构,不清空配置或会话历史;已有的一次性定时会迁移成新的 schedule 实体,原有的触发时间保留。

这一版里有**两个迭代点**。它们本来该各自一个版本号,但后端和前端是叠在一起的一个栈、必须一起落地(后端单独上线等于给用户一个没有界面的能力),所以合在同一版发布。下面分开讲。

## 新增 · 定时

**Bot 可以按周期自己醒来了。** 以前只能设"某个时刻跑一次",现在四种都能设:一次、每天、每周、每 N 小时。在 Bot 聊天框的发送按钮旁边就能设。

右侧抽屉里有一份管理列表:每条定时的规则、下次触发时间、上次结果、重叠策略都在那儿,可以暂停、修改、删除,带配额提示(每个 Bot 最多 20 条)。

**列表会如实说出每条定时现在的状态**,五种分得开:

- **待触发** —— 正常排着队
- **已暂停** —— 你自己停的,它不会触发
- **已到点但被挂起** —— 到点那一刻 Bot 被暂停了、或者上一轮还在跑,**恢复之后会补跑这一次**
- **已执行完** —— 一次性定时跑过了,不会再来
- **上次没能建出任务** —— 到点会再试,不是已经执行完了
- **记录损坏** —— 这条读不出来,改规则或时区后再启用

第三种和第六种是这一版专门收口的:**被挂起不等于出错,也不等于逾期**,所以它用的是 amber 而不是错误色,并且明说恢复后会补跑。

**自动唤醒总闸和单条暂停分开了。** Bot 的自动唤醒关掉时,列表顶部有一条横幅说明"列表里的定时都被总闸拦住,到点不会触发 —— 这不是单条的已暂停",每一行也会标出来。两层闸不会再混成一个状态。

**一次性定时不会被一次失败吃掉。** 如果到点那一刻模型不可用、任务根本没建出来,这条定时会把它唯一的机会还回去,等可用了补触发。而且在不可用期间它不会每轮重写状态文件 —— 实测连续 10 次失败的 tick,状态文件一个字节都没动。

## 新增 · 在对话里换模型

**在 Bot 聊天里说"换成 glm-5.3",它就换。** Bot 先去拿当前通道**真实可用**的模型清单,恰好匹配一条才切;匹配到好几条时会把候选列出来让你挑,而不是自己猜一个;一条都没匹配上时会如实说,并列出可以选的。

切换**从下一轮任务起生效**,本轮仍用原来的模型 —— Bot 会把这件事说清楚,而且聊天页头部一直显示 `当前 X · 下一轮 Y`。

聊天框里的捷径("把模型改成 X")走的是同一套匹配和同一种语义,不会再和后台任务抢。

两个边角也一起处理了:**换成当前已经在用的那个模型,不会白扔掉整个会话**(以前会重开一个新会话,而模型一个字没变);**待生效的那个模型如果在这期间掉线了,不会把 Bot 卡死** —— 它会取消这次切换、指名那个不可用的模型、本轮继续用当前模型跑完,而不是之后每个任务都失败。

## 已知缺口

**计划里给某一步指定模型,目前对跑过任务的 Bot 不生效。** 这是 Bot 协作(计划分工)里的一条老路径,不是这一版新引入的:计划步骤上写的模型会被算出来,但启动时如果复用了 Bot 已有的会话,那个模型就被丢掉了,而且没有任何报错。已经立包待修,当前用一条测试明确标注着这个状态。

**Bot 编辑器目前没有打开入口。** Bot 的设定走 Header 右侧的「设定」抽屉;编辑器里那几行模型显示是预留接线,现在看不到。

# v4.17.0 · 识图借用扩展到 Claude 和 OpenCode，更新完会告诉你变了什么

## 不能识图的模型，可以去借一个能识图的

- **Claude Code 和 OpenCode 也能识图了**（#216）：Pi 早就能做这件事——主模型读不了图时，`describe_image` 把图转发给同一个通道里能读图的模型，回灌纯文字。另外两个 harness 之前什么都没有，截图在那里基本没用。现在它们通过一个 MCP server 用上同一个池子。
- 池子规则没有重写：谁能读图，全局只有一处答案，来自你自己通道里的模型和能力判定，没有内置模型名单，也没有优先级。你在 Pilot 里勾选「可读取图片」，Claude 和 OpenCode 立刻跟着变。
- 主模型自己能读图、或本通道没有能读图的模型时不会注册这个工具；切到能读图的模型时会把它取走。
- Codex 不接入。
- 想关掉：`session_surfaces.disabled` 里写 `mcp:vision`。

## 更新完会告诉你变了什么

- **新增「已更新到 x.y.z」面板**（#216）：更新对话框只在你确认**之前**展示发布说明，更新完页面刷新后之前什么都不说。现在首页会显示这一版的发布说明，每个版本只显示一次。
- `升级须知` 单独拎在最前面，其余内容默认折叠，不会把输入框挤出屏幕。
- 说明从安装目录里读，不依赖网络，也不会显示成一个你并没有在跑的更新版本。

## `~/.config/mms` 彻底退出

- **五处还在用旧目录的代码改掉了**（#215）：OpenCode 的导出配置、健康看门狗的整个配置目录、public copy 的更新检查、两处 bundle 兜底。它们在配置根搬走之后还在往旧目录写。
- **Claude 状态栏在新布局下能找到路由信息了**（#215）：脚本只会从 `~/.config/mms` 的 gateway home 往上走，当前布局下它把配置根算成一个不存在的路径。顺带修了它十处读文件时间的方式——那是 macOS 专用写法，**在 Linux 上整个路由和健康显示是死的**。
- 人工确认页不再写错要改的文件，README 增加了一节说明只有一个配置根、以及 runtime 真值从哪来。

## 升级须知

- 本次会替换安装目录里的 `mms`、`mmf` 和 Pilot。如果同机有 `mms` 会话在跑，建议等它结束再更新。
- 更新过程中 Pilot 会重启，页面会自动刷新；重启期间已在跑的网页会话会短暂断开。
- 识图借用需要本机有 `node`。Pilot 和各 CLI 本来就依赖它，没有额外安装步骤。
- 借用识图会向被借的那个模型发一次请求，按那个通道的用量计费。主模型自己能读图时不会发生。
- OpenCode 的导出配置从 `~/.config/mms/opencode-gateway/` 挪到了 `~/.config/mms-next/opencode-gateway/`。每次启动都会重新生成，不需要你做什么；旧目录可以自行删除。

# v5.0.2 · 日常界面收口，TUI 里多了 Grok

## 升级须知

5.x 是预览线，Bot 工作台仍在打磨。本版本的改动集中在日常交互和启动器，不改 Bot runtime（记忆、协作、定时、coordinator、Pi 执行一律未动），没有新的配置项，不清空配置或会话历史。

本版本包含 4.22.2 稳定线的全部内容。

## 新增

- **TUI 里可以选 Grok Build 了。** 和 Pi 同级的启动器：选模型和 provider 之后用隔离的 `GROK_HOME` 启动，把当前通道的模型写进这次会话自己的 `config.toml` 并钉死可选范围。全程不读你真实的 `~/.grok/auth.json`。Claude 走 Anthropic Messages，其余走 chat completions；对 MiniMax / NewAPI 那种流式缺字段的上游，本机会起一个只听 loopback 的兼容代理补齐，用完随进程退出。

## 修复与调整

- **聊天里的通道显示收口。** 日常只显示模型名，只有多通道时才出友好名徽章；「通道与高级选项」改叫「高级选项」；输入框上方的状态行带上模型和通道。
- **设置页整理。** 运行环境的诊断信息归到一处，通道的「检查并保存」贴在滚动底部，离开确认的主按钮改成「检查并保存」。
- **Bot 设定挪到了看得见的地方。** Header 右侧的「设定」抽屉里放默认模型、自动唤醒和工作方式，左侧 `⋯` 不再有「编辑 Bot」。从某个会话进入 Bot 之后，「返回对话」会回到原来那个会话，不再丢。
- **设置里复制路径不再依赖安全上下文。** 明文 HTTP（手机和局域网访问走的就是它）下也能正常复制。

## 从 4.x 过来

`main` 上的每一处改动都默认进入这条线，所以 5.x 永远是 4.22.x 的超集。两条线在同一台机器上不能共存，换线重跑安装器带 `--channel dev` 或 `--channel stable`，配置和会话历史都在同一个 config root 里，不会被清掉。

**目前只能从终端换线**，Pilot 的更新入口里还没有「切到另一条线」的开关。更新探测读的是 GitHub 的 `releases/latest`，而 5.x 的 tag 都标成 Pre-release，所以稳定线的更新检查看不到它们。这是已知缺口，不是设计如此。

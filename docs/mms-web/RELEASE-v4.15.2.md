# v4.15.2 · 修复「明明装了 pi 却装不上」

- **全局装了 pi 但 bin 不在 PATH 时，安装不再中止**（#205）：`scripts/pi-cli-wrapper.sh` 以前只认 `MMS_PI_EXECUTABLE` 这个环境变量，安装脚本直接调用它时该变量为空，于是直奔 npx 缓存；而包已全局安装时 `npx --cache` 根本不会往缓存里装东西，缓存永远是空的，wrapper 报「cache warmup did not produce an executable」。v4.15.1 把这一步改成了致命错误，于是整个安装中止——尽管安装脚本第一行就报告「✓ 已检测到: Pi coding agent」。
- 现在 wrapper 会先找已安装的 pi：PATH 上的，或 `npm prefix -g` 下的，找不到才用缓存；预热没产出时再找一次。命令行与网页端改用同一个解析器，从访达或安装脚本启动的会话也能找到 pi。
- 安装失败时的文案改为如实说明三处都没有，并给出补救命令。

## 升级须知

- 上一版（v4.15.1）在部分机器上会让安装中止，本版修复。如果你卡在那一步，直接重跑安装命令即可。
- 本次仍会替换安装目录里的 `mms`、`mmf` 和 Pilot；如果同机有 `mms` 会话在跑，建议等它结束。

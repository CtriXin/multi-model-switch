# Decision Judge Module — 设计摘要与实施指南

> 给其他 Agent 的上下文文档。基于 Judge Integration Brief 原文 + 多轮讨论结论。

---

## 一、这个模块要解决什么问题

多模型并行回答后，简单地"总结各家观点"不够用。用户需要的不是"谁说了什么"，而是：

- 现在可以安全做什么
- 哪些地方还需要验证
- 有什么风险
- 什么条件下建议会失效

**一句话：从"中立总结"升级到"决策支持"。**

---

## 二、架构位置

```
用户提问
  ↓
多个模型并行回答（已实现）
  ↓
Judge 模块（= 升级版 Summarizer）
  ↓
结构化输出：共识 / 分歧 / 风险 / 建议行动
```

Judge 不是新的独立系统，它取代原来的 Summarizer 位置，用同一条调用链路（`streamChat()`），区别只在 prompt 和输出结构。

实现约束补充：

- Judge 的流式内容要实时写回 chat round，而不是只保存在组件本地
- 已完成或部分完成的 Judge 结果要随 session 一起恢复，回到页面后能立即显示
- 若用户在生成过程中切页，至少要保留已生成内容，不能因为组件卸载直接丢失

## 三、分层策略（成本 vs 可靠性）

### Tier 1 — Standard Judge（默认，始终运行）

- **触发**：所有模型回答完成后自动触发
- **做法**：一次 API 调用，structured prompt
- **输出**：共识 / 分歧 / 风险 / 建议行动 / 不确定性声明
- **成本**：等于一次普通模型调用
- **评估模型选择**：从未参与回答的模型中按 tier 降序选（Premium → Standard → Free）；全部不可用时用回答模型中 tier 最高的

### Tier 2 — Risk Review（条件触发）

- **触发信号**：
  - 回答之间冲突度高（长度方差大、关键词矛盾）
  - 用户主动点击「深度审查」
- **做法**：在 Tier 1 基础上，将交叉审查（cross-critique）结果也喂给 Judge 作为额外输入
- **成本**：比 Tier 1 多出交叉审查的调用

### Tier 3 — Committee / Deep Review（暂不实现）

- 多轮对抗评估
- 最高可靠性，最高成本
- 等 Tier 1/2 验证后再考虑

**核心原则：可靠性来自评估协议和输入结构，不是来自堆模型数量。**

## 四、单模型场景怎么办

当系统只有一个模型时，Judge 和回答者是同一个模型。直接让它"评估自己"会陷入 echo chamber。

### 解法：三层缓解，不设门控

**1. 透明标注**

| 场景 | UI 显示 |
|------|---------|
| 多模型 | 「基于 3 个模型对比评估」 |
| 单模型 | 「单模型自评（可靠性有限）」 |

不由系统判断"够不够可靠"，让用户自己校准信任度。

**2. 断开上下文的 blind self-evaluation**

拆成两次独立 API 调用，不共享对话上下文：

```
第一次调用：正常回答问题 → 得到回答 A

第二次调用（独立 context）：
  "以下是一个匿名回答，请找出其中的问题、风险和盲点"
  + 回答 A 的内容（不标注来源）
```

关键：第二次调用不知道答案是谁写的，避免模型维护自己答案的 sunk cost bias。

**3. 强制保守约束**

单模型 Judge 的 prompt 中加入硬约束：

> "你只有一个信息来源。在 uncertainty 字段中，默认从「中等不确定性」起评，除非有充分证据支持更高确信度。"

与其让系统事后猜测评估是否可靠，不如在源头逼模型保守。

## 五、输出结构

Judge 的输出不是选出"最佳回答"，而是：

```json
{
  "consensus": "各模型达成一致的部分",
  "conflicts": "有分歧的部分及各方立场",
  "risks": ["风险1", "风险2"],
  "recommendation": "建议的行动方案",
  "uncertainty": "不确定性声明 + 等级",
  "invalidation_conditions": "什么条件下这个建议会失效",
  "source_label": "基于 N 个模型对比评估" | "单模型自评（可靠性有限）"
}
```

**前端展示**：默认只展示 `recommendation`，其余折叠。用户展开可看完整分析。

## 六、关键设计决策总结

| 问题 | 决策 |
|------|------|
| Judge 什么时候运行？ | Chat：回答完成后自动。Discuss：Phase 3 位置 |
| 总是输出完整结构吗？ | 是，Tier 1 成本低无需省。UI 层折叠即可 |
| 所有回答都弱怎么办？ | prompt 里要求：信息不足时明确输出"不足以做决策，建议补充 XX" |
| casual vs expert 用户？ | 默认折叠只看建议，展开看完整分析 |
| 单模型可靠吗？ | 不完全可靠，但有价值。透明标注 + blind eval + 强制保守 |
| 成本控制？ | prompt 协议 → 结构化输入 → 选择性升级。不堆模型 |

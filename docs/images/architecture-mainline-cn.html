一个 launcher surface，多种模型，显式 routing 与 isolation

MMS 运行时流程

当前 reality：MMS 先加载配置，再解析 adapters 与 route policy，最后从同一个 control plane 启动隔离的 Claude/Codex 会话，或导出 routes 与 diagnostics。

Entry Surfaces 操作者真实能看到的公开入口

Install & Packs
install.sh 负责安装 MMS 本体，也能顺手装 RTK、MindKeeper context、Map、read-once、ops-env-safe 等 optional packs。
bootstrap
TUI & CLI
mms、mms claude、mms codex 等命令提供统一的本地 launcher surface。
human operator
Web / Runtime API
apps/web 与 apps/runtime-api 提供额外的 operator / integration surface。
optional surface

Core Runtime / Workflow 配置如何变成实际 launch 与 routing 决策

Load Config & State
从真实的 MMS config tree 读取 config.toml、overrides、accounts、env files、usage 与 gateway session 上下文。
human-only config guard
→
Resolve Adapters
通过 adapter registry 与 family 规则，把 model families、CLI capabilities、provider/account 元数据拼到一起。
family-first
→
Route & Classify
把 keyword guardrails、LLM classification、sticky escalation、role、priority 合并成最终 provider / lane 选择。
light / medium / heavy
→
Launch or Bridge
按解析出的 env 与 route selection 启动隔离的 Claude/Codex sessions、gateway bridges 或 API-facing flow。
gateway sessions
→
Export & Diagnose
把 route exports、usage、speed stats、diagnostics 写出来，让 operator 看清 MMS 下一步会怎么跑。
routes / doctor / test

Artifacts / Operator Surfaces 持久配置、导出路由与 operator 工具面

Config Tree
~/.config/mms/ 保存 legacy config、accounts、env、usage 与 session state；人只通过 TUI / mms config / WebUI 操作。
human config / state
Registry Bundle
generated/model-registry.latest-approved.json 校验 generated Router / Lineup / Profile / Policy / Capabilities；root route 文件只是 compatibility exports。
latest-approved
Operator Surfaces
mms routes、doctor、test、warm 与 TUI 让操作者能观察并干预系统。
observe / steer

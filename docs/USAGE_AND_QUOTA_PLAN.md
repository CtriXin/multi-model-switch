# 使用统计与额度计划

## 当前已落地

### A. 手工元数据

- `provider` / `account` 都支持：
  - `priority`
  - `cost_level`
  - `daily_budget`
  - `note`
- 这些字段用于后续排序、推荐和人工调度参考
- 当前不会自动执行额度控制

### B. 本地软统计

- 本地会记录每次启动：
  - 来源类型
  - 来源名称
  - CLI
  - 启动次数
  - 最近模型
  - 最近使用时间
- 统计文件路径：
  - `~/.config/ccs/usage.json`
- 查看命令：
  - `./mms config stats`

## 这轮不做的事

- 不做官方 OAuth 真实余额查询
- 不做 provider 实时 billing 拉取
- 不做自动按额度切换
- 不做失败率/成功率精确统计

## 四象限 Todo

| 象限 | 项目 | 说明 |
| --- | --- | --- |
| 高价值 / 低成本 | 按当前模型动态过滤来源 | 选了 `MiniMax` 后，只显示命中该模型的 provider |
| 高价值 / 低成本 | 来源排序融合 `priority + 最近使用` | 让默认来源更贴近真实使用习惯 |
| 高价值 / 高成本 | provider 真实 usage / billing 接入 | 仅适用于有稳定 billing API 的网关 |
| 高价值 / 高成本 | 自动按额度/冷却时间切换 | 需要可依赖的真实用量数据 |
| 低价值 / 低成本 | `config stats --json` | 方便脚本化读取本地统计 |
| 低价值 / 低成本 | 在来源列表里显示成本等级 badge | 纯体验增强 |
| 低价值 / 高成本 | 官方 OAuth 账号真实余额探测 | 高概率不稳定，不建议优先做 |
| 低价值 / 高成本 | 跨设备同步使用统计 | 首轮没有必要 |

## 建议顺序

1. 按当前模型动态过滤来源
2. 用 `priority + 本地软统计` 做来源默认排序
3. 只给自有 provider 接真实 billing/usage
4. 最后再讨论自动切换

# MMS Web 设计系统

## 产品方向

一个顺手的本地对话工具。日常操作围绕输入、阅读、定位与继续工作展开；不使用工作台、后台指标或配置卡片墙。MMF 继续负责模型、通道、隔离运行，不另造配置源或 agent loop。

2026-09-08：用户不满意此前三张设计图。A 仅临时参考，视觉尚未验收；实际页面交互与读起来是否清楚是当前主要判断依据。

## 信息结构

- 侧栏保留新会话、搜索、工作文件夹与设置。所有/待回答/错误/归档集中到筛选；真实待回答才显示相应提示。
- 新会话以输入为中心：内容、Skills、工作文件夹与单个任务设置。模型/通道/effort/模式归入同一 popover，首页不铺模型卡片。
- 设置汇集模型与通道、外观与使用。真实 MMF 配置仍只读；独立可写配置使用 preview/apply。连接向导已在独立配置服务完成地址/Key、模型拉取/手填、预览保存和 effort 验证；现有 8765 backend 尚未重启加载新增 API，不能把独立验证算作真实配置已可写。
- 同一用户轮次只显示一次 assistant 身份；连续工具调用归入紧凑组，每行展示真实名称与命令/路径摘要，展开看参数和输出。Thinking 保留可展开内容，过程中间文字收紧，最终回答保留阅读层级。
- 成果和运行详情按需打开。提问定位平时仅显示右侧细刻度，hover/focus 展开原文，当前提问高亮，点击定位。不是常驻目录面板。

## 视觉

studio.css 提供中性语义色，states.css 处理状态，transcript.css 处理会话阅读与定位。浅色侧栏 #f3f4f8，阅读画布白色，默认强调色 #5856d6。靛蓝、海蓝、玫瑰、琥珀可在外观中切换，深色模式使用独立语义值。成功绿色仅用于完成语义，amber 用于等待，red 用于失败。

系统 SF/PingFang sans；正文 15px，中间说明 13px，工具行 12px，命令 monospace。会话上限 920px，正文与工具摘要对齐；输入区保留轻微阴影。避免装饰竖线、渐变发光、巨大标题和重复头像。选中行采用整体轻染和细边界。

## 交互约定

- idle 是原生进程状态。无失败/停止活动的回合在 UI 中显示本轮已完成；进程退出与本轮完成分开。新产出以实际输出指纹标记新回复，看到结果后清除未读，保留完成标签。
- 定位提问会暂停跟随新输出并短暂标记原文。鼠标移到展开目录文字时保持打开，移出收起；键盘方向键、Home/End、Enter、Escape 可用。触屏点击展开。长目录可滚动，目录在收起状态下保持当前刻度可见。
- 回到最新消息恢复跟随；浏览历史时新输出不得抢走阅读位置。工具组的折叠状态在数据更新后保持。
- 消息操作 hover/focus 显示；触屏常显。隐藏按钮不拦截 pointer 事件。用户消息可复制，assistant 消息另可创建分支；用户消息分支尚无 backend 支持，不显示假按钮。
- native dialog/popover 支持 Escape 和点击外部关闭。Enter 发送，Shift+Enter 换行，composition 不误发。任务设置只影响当前任务，同模型保留 effort。
- 普通会话/新任务草稿按键分开保存 7 天，最多 30 个，保留文字、Skills、引用、附件元数据；浏览器不持久保存 base64。刷新后向本地服务恢复缩略图，附件失效明确提示。任务模板导入的临时草稿仍受导入 key 生命周期限制。
- 窄屏折叠主导航，popover 不越界。动画依据实际事件，断连不假装忙碌；支持 reduced motion。

## 验证边界

真实 Pi 配合 task-owned 本地 provider 验证状态与工具事件。额外合成八轮历史仅用于多轮工具、hover、定位、流式追加、草稿与窄屏回归，不冒充真实模型能力。普通 localhost URL 检查实际加载 bundle 与真实会话，前端可独立更新，禁止为样式重启用户的后台和 Pi 会话。

## 阅读交互补充（2026-09-08）

- 消息下方操作区从正文边缘连续延伸，hover 到按钮不穿过空白断带；直接进入底部和键盘 focus 同样可达，触屏保留至少 40px 高度。中间回复的操作区不覆盖下一组工具。
- Markdown 以 CommonMark + GFM 为基础。仅 assistant 展示兼容缺空格的 2–6 级标题，以及有序列表里粘连的下一编号加粗标题；代码、链接内部与原文不自动改写，复制/导出仍使用原文。
- Markdown renderer 保持组件身份，流式数据刷新不重置代码复制反馈。
- 对外称任务模板：保存首条任务文字、模型偏好和规划开关，不自动附带连接凭据、附件或后续对话；文字原样保留。旧 mms-work-recipe-v1 继续可读，导入后先进入草稿，用户发送后才执行。

## 通道设置的生效范围（2026-09-08）

设置中的可用通道选择即时同步新会话 presetId，并保存当前浏览器偏好；再次进入设置默认显示该组合。顶部文字明确显示新会话实际选择。不可用通道只允许查看，不覆盖可用的启动选择。默认 effort 在设置中变更后清除该通道旧的新任务临时覆盖；已有会话的 runtime 不因此改变。模型配置、Key、路由优先级仍由 MMF 原配置负责。

## 通道模型管理（2026-09-08）

“模型与通道”内新增“管理通道模型”，采用通道选择、搜索、紧凑模型列表和固定保存入口，避免展开整个技术配置后台。

- 当前目录从 verified latest-approved bundle 读取。隐藏历史模型可展示，但不能把它们误当成用户请求删除的路由。
- 拉取复用现有通道与 MMF provider probe，probe 只在私有快照中更新缓存。新增模型默认不勾选，接口未返回的已选模型不自动移除；手工目录不自动改成远端 probe。
- 模型勾选限当前通道；MMF 默认 effort 按模型 ID 保存。下拉框使用当前 Pi 路由实际支持且 MMF policy 能表达的档位；与浏览器内 Web 默认 effort 明确区分。
- 保存先显示模型增删和跨通道 effort 影响，再走现有 Config Web 的确认、审计、备份、Registry 发布与校验。真人可在此入口确认写入 mms-next，agent 的真实配置写入禁令保持有效；稳定安装根不因此开放写入。
- 全局 runtimeReady 为 false 不等于所有通道都不能用。保存结果应说明仍有通道未就绪，不能误报当前可用通道停止服务。

## 连接与默认值（2026-09-08）

通道设置内按需展开连接地址与 API Key；OpenAI/Anthropic 地址保持独立，Key 使用空的密码输入框，留空保留。检查操作使用当前草稿，明确只验证模型列表接口，不把 GET 成功称为生成可用。手工通道不额外 probe。修改连接与模型默认值统一进入已有变更预览。

默认 effort 提供“恢复自动”，实际删除用户覆盖值，保留模型能力事实。展示值区分显式 policy 与默认推导，禁止用一个固定 high 冒充自动。

- 本地文件优先引用原路径：系统选择器或粘贴路径产生文件 chip，显示本地来源和大小，图片提供缩略图；不复制文件、不要求上传。浏览器拖放缺少原路径时显示中性引导，不能假装知道路径。无原路径的剪贴板截图才保存为附件。

## 独立配置默认值（2026-09-09）

独立 Web 配置复用通道模型管理，长期默认 effort 与本次会话覆盖分开。保存显示变更与存储目录，独立配置使用“保存设置”确认文案；既有 MMF 来源沿用原生确认合同。旧独立配置只在用户明确保存时采用 Registry，读取和预览不会写入来源。

# Web-V2 Mock Demo Guide

## 目标

让 `Demo (模拟数据)` 在 Chat / Discuss / Advisors 三条链路都能看起来像真实业务演练，并稳定触发一次失败重试流程。

## 关键变化

- 首次进入新增 `体验模式` 分流：
  - `立即体验 Demo`：无 Key 直接进入 Chat/Discuss/Advisors mock 全流程。
  - `连接我的模型（BYOK）`：继续在引导页填写个人 API Key（纯前端，不依赖后端）。
- 首页默认改为 `快速开始体验模式`（`/` 直接进入引导页）。
- API Key 预设列表支持 `一键隐藏/展开`（适合预设较多时快速收起）。
- 增加了多组 demo agent（模型池更丰富，包含推理、快速、平衡组合）。
- 对网关返回“无档位/同档位”的模型列表，新增统一评分回退：
  - 当同一通道模型都落在同一档位时，系统会按价格、上下文、能力与命名信号自动重排。
  - 自动重排后会分到 `主力/旗舰` 两档，避免全部挤在同一档位导致筛选体验失真。
- 保留了 2 个故障 agent，用于演示 retry：
  - `demo/offline-strategy-agent`（模拟 `model_unavailable`）
  - `demo/throttled-risk-agent`（模拟 `rate_limited`）
- 决策评估（Judge Agent）现在包含 `各回答评分` 段落。
- 模拟内容收敛为 2 类场景：
  - `新对话`（简短结论 + 动作 + 风险）
  - `锦囊团`（角色评审/主持人收敛）
- Discuss 的 Phase1/Phase2/Phase3 与 Rollup 仍返回结构化内容（JSON + Markdown）。
- Advisors 的三阶段输出按预设格式返回：
  - 角色输出：`【判断】/【观点】/【张力】/【建议】`
  - 辩论输出：`【反驳】/【立场】/【吸收】`
  - 主持人输出：`共识/分歧/动作/少数派`

## 推荐预设

- `全流程演示`：用于完整展示多模型并行 + discuss + advisors。
- `故障演练`：用于稳定演示失败与重试路径。
- `快速响应`：用于短时间展示完整答案结构。

## 触发词（可直接复制）

### Chat

- `新对话：给我一个三步执行方案。`
- `chat：先给结论，再给动作和风险。`

### Discuss

- `主题：Q2 增长计划要不要先降价拉新，还是先优化转化漏斗？`
- `主题：本周要不要先重构消息链路，还是先补可观测和熔断？`

### Advisors

- `锦囊团：新版本两周后上线，如何兼顾增长目标和审核风险？`
- `committee：跨团队延期，怎么重排里程碑？`

## 演示顺序建议

1. 打开应用默认进入首页快速开始（`/`）。
2. 如预设太多，可先点 `一键隐藏预设` 收起 API Key 列表。
3. 点击 `立即体验 Demo` 进入主流程。
4. 用 `全流程演示` 预设跑 Chat，看结构化完整答案。
5. 切到 Discuss，输入同一主题，展示三阶段输出和 Rollup。
6. 切到 Advisors，使用 committee 模式展示角色分工与主持人收敛。
7. 切换到 `故障演练` 预设，触发失败后点击重试或替换模型。

## 无后端策略（开源默认）

- 默认给新用户 `Demo` 可体验路径（无 Key 可跑全流程）。
- 真实模型统一走 `BYOK`（用户自行提供 Key）。
- 不在客户端内置共享平台 Key，避免泄露与审核风险。
